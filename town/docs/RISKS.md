# 风险与合规清单

## 产品风险

1. **做成商业黄页**：打开地图全是广告和店铺，普通玩家不会留下。
   - 对策：首页只有城市与小人；商业地图需要主动进入；不开店也能完整地玩；赞助可关闭。
2. **AI 匹配变成虚假承诺**：
   - 对策：所有推荐标注“系统推测 / 系统估算 / 需求未确认”；信息不足不打分；每条都有理由与来源；可拒绝。
3. **范围无限扩大**：3D 城市、多人实时、商业平台、Agent 本身就是四个复杂系统。
   - 对策：按 `ROADMAP.md` 分阶段，每阶段有验收标准再投入下一阶段。

## 合规与数据

| 领域 | 风险 | 当前做法 / 上线前必须完成 |
| --- | --- | --- |
| 地图与测绘 | 使用未授权地图数据、截图、抓取建筑数据 | Demo 只用近似坐标手工示意路网；上线前取得地图服务商授权，遵循测绘资质、数据授权与坐标规范；不内置坐标纠偏算法 |
| 历史建筑 | 凭空编造外观、误导性历史信息 | 只收录较确定信息，其余“待核实”；模型审核状态可见；文保建筑不设商业铺位 |
| 个人信息 | 画像、联系方式、位置泄露 | 画像需确认才公开；联系方式双方同意才可见（RLS）；不读取聊天记录推测隐私；可关闭“被推荐” |
| AI 透明度 | 访客误以为在和真人交流 | Agent 每次对话前声明身份；“你是真人吗”如实回答；主理人可随时接管 |
| AI 越权 | Agent 擅自报价、打折、签约、承诺 | L3 永远转交本人；只引用 `price_confirmed` 价格；所有回复记录 citations 与审计日志 |
| 生成式 AI 服务 | 接入大模型需符合生成式 AI 服务相关管理规定 | 使用国内合规模型 API；上线前完成相应备案/安全评估流程；内容安全过滤 |
| 广告与赞助 | 赞助伪装成自然推荐、买排名、刷口碑 | 赞助明确标注；无买排名接口；口碑只来自经核实的真实交易 |
| 虚拟货币 | 积分被包装成投资收益或变相金融交易 | 星星/成长值不可兑换、不可转账；代码层不提供相关能力（单测保证） |
| 支付 | 自建支付、二清风险 | 不自建支付；先询价/意向单，再接持牌支付机构 |
| 企业身份 | 用户误以为开虚拟店 = 注册公司 | 三种主体状态明确区分；“已认证企业”需平台审核 |
| 演示数据 | 虚构角色被当作真实商户 | 全部标注“演示角色 / 演示店铺”，虚构联系方式；`is_test_account` 不计入统计 |
| 线下活动 | 安全、收费纠纷 | 收费与争议处理由主理人本人决定，AI 主持人不处理；平台规则与免责声明（待法务） |

## 技术依赖

- three.js / React Three Fiber / drei：3D 渲染（WebGL；低端机需降级：关阴影、降 DPR）。
- Supabase：Auth、Postgres、Realtime（国内访问需评估合规云部署或自建 Postgres + 同等能力）。
- 地图数据：需授权数据源。
- 大模型 API：可替换，国内合规模型。
